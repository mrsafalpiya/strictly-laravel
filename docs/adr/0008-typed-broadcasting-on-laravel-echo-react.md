# Typed broadcasting wraps Laravel's `@laravel/echo-react`, keyed by Echo's own event names

A broadcast event returns its payload from `broadcastData()`, declaring a Data class (the `BroadcastsData` trait turns it into Laravel's `broadcastWith()` array), and the client listens with `useChannelEvent(channel(pattern, params), name, cb)` from the generated `@/generated/broadcasting`, a thin wrapper that calls `@laravel/echo-react`'s `useEcho()`. We build on `@laravel/echo-react` because `php artisan install:broadcasting` installs and configures it (`configureEcho()`) for every React app, so the Overlay adds no client, connector or configuration of its own and only narrows the types; its own `Events` interface is hand-written and its `useEcho()` falls back to any string, so it can't be used directly (Problems P-052, P-053). Events are keyed by the name Echo listens for them under its default namespace (`CommentPosted`, `.comment.posted`) rather than by Laravel's broadcast name (`App\Events\CommentPosted`), so a listener reads as it would with `useEcho()`; the wrapper still listens for the absolute name, so the app's Echo namespace option doesn't matter. Generated event objects or per-channel functions were the alternative, at the cost of more generated runtime code and names that collide across namespaces.
