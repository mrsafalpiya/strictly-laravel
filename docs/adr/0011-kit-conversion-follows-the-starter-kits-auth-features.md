# Kit Conversion follows the starter kit's auth features through sections in one converted file

The React starter kit asks which of five auth features to keep (email verification, registration, two-factor authentication, passkeys, password confirmation) and cuts the others out of its files with `laravel/chisel` while `laravel new` runs, so the Base Kit an app starts from is one of 32 variants (P-211). Each file under `kit/` stays one file, with `@feature <condition>` sections that the installer keeps or drops for the features the app has (read from `config/fortify.php`, and from whether its `FortifyServiceProvider` registers the confirm-password view); `kit-conversion.json` lists each file's upstream hash per combination of the features it varies with, and the `config/strictly.php` stub declares each feature's vendor routes in a section of its own. The hashes come from the harness, which rebuilds every variant from the Base Kit and the kit's repository at the same commit by running the kit's own script, so an upstream change to any variant fails `pnpm test` as one to the full-featured kit does (ADR-0005). Chosen over one converted copy per variant (up to 32 copies of `FortifyServiceProvider.php` to keep in step) and over supporting only the full-featured kit (an app that turned a feature off would have no way onto the Overlay but converting by hand). Rendering with every feature kept gives each file exactly as it was before it had sections, so apps converted by an earlier release see no change.
