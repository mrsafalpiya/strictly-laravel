# Laravel + Inertia + React — type-safe starter

The official [Laravel React starter kit](https://github.com/laravel/react-starter-kit) (Laravel 13, Inertia v3,
React 19, Tailwind 4, Fortify auth with 2FA + passkeys) with **end-to-end type safety that needs no manual steps**:
you write PHP, and the TypeScript for every page prop, form, enum, shared prop, flash message and route appears
on save.

```php
// app/Pages/Projects/ShowPage.php
final class ShowPage extends Page
{
    public function __construct(
        public ProjectData $project,
        /** @var Lazy|array<int, ActivityData> */
        public Lazy|array $activity,          // deferred
    ) {}
}

// app/Http/Controllers/ProjectController.php
public function show(Project $project): ShowPage
{
    return new ShowPage(
        project: ProjectData::fromModel($project),
        activity: Lazy::inertiaDeferred(fn () => ...),
    );
}
```

```tsx
// resources/js/pages/projects/show.tsx — props are generated, routes are generated
export default function Show({
    project,
    activity,
}: PageProps<'projects/show'>) {
    return <Link href={edit({ project })}>{project.name}</Link>; // activity?: ActivityData[]
}
```

Rename a PHP property, remove a route, add an enum case, make a field nullable — `tsc` points at every React line
that has to change.

## Getting started

```bash
composer setup     # install, .env, key, migrate, pnpm install, build
composer dev       # server, queue, logs, Vite — types regenerate on every PHP save (~1s)
```

New page: `php artisan make:page projects/show` (creates the PHP Page class and the typed React component).

## How it works

| You write (PHP)                                  | Generated (TS)                                                                                             | Tool                                           |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `App\Pages\…\XPage` (one per Inertia page)       | `PageProps<'x'>` + compile-time check that `pages/x.tsx` exists and accepts exactly those props            | `InertiaPagesProvider` (this repo)             |
| `App\Data\…` laravel-data classes (props, forms) | `export type XData = {…}`                                                                                  | spatie/laravel-typescript-transformer v3       |
| Backed enums in `app/`                           | `'a' \| 'b'` unions                                                                                        | same                                           |
| `App\Data\SharedProps`, `App\Data\FlashData`     | `InertiaConfig['sharedPageProps' \| 'flashDataType']`                                                      | `InertiaPagesProvider`                         |
| Routes + controllers                             | `@/routes/*`, `@/actions/*`                                                                                | laravel/wayfinder                              |
| Action parameters / return types                 | typed `query` options (`QueryData`), `.form()` branded with the payload (`InputData`), JSON response types | Wayfinder templates + `RouteTypes` (this repo) |

All of it is regenerated by Vite plugins (`vite-plugins/php-types.ts`, Wayfinder's plugin) in `dev` and `build`,
and by `composer types`. Generated files are gitignored.

And then it is _verified_, not trusted:

- **Contract tests** — every Inertia response produced by any feature test is recorded as
  `export const props = {…actual JSON…} satisfies PageContract<'x'>` (`tests/Support/InertiaContracts.php`),
  so `tsc` proves the generated types match what the server really sends.
- **PHPStan level max** (Larastan, strict-rules, bleeding edge, 100% type coverage) — the PHP that builds the
  Data objects is itself fully typed, including tests (pest-plugin-phpstan).
- **Arch tests** — no `Inertia::render([...])` with untyped arrays, every page file has a Page class,
  every `App\Data` class is a final laravel-data class.
- **Contract coverage** — `php artisan types:coverage --strict` fails when a page, deferred prop, JSON endpoint or
  form is never exercised, a declared vendor field is never validated or read, a route key sent doesn't exist, or
  a nullable field is only ever `null`, a list only ever empty, a union variant never seen.
- **Typed names** — prop names go through `forPage<'x'>()` (`only`, `Deferred`, `InfiniteScroll`, …; lint rules in
  `lint/type-safety.js` reject raw strings), and form-field names through `<TypedForm>`'s `field('name')`, a branded
  `FieldName`. The app's JSX types require it for `name` on every form control, React's raw `<input>`/`<select>`/
  `<textarea>`/`<button>` included (`resources/js/types/jsx/jsx-runtime.d.ts`), so `tsc` checks it everywhere.
- **Requests typed by their route** — `useRouteForm(store(workspace), defaults)`, `submit(update(route), data)`,
  `visit(destroy(route))` and `useRouteHttp(search(workspace), …)` (`@/lib/requests`) take the payload, the
  validation-error keys and the JSON response type from the route, never from a hand-picked type argument. Lint
  rejects Inertia's untyped `useForm`/`useHttp`/`router.post(url, data)`, hard-coded URLs, and `as`/`!` casts
  outside three documented boundary modules. Enum value lists are generated from PHP (`enumValues`).
- **Nominal route parameters** — `show({ project })` takes a `RouteKey<'Project', string>`: a ProjectData, its
  `key`, or a field declared `#[RouteKeyOf(Project::class)]`; not another model with a `key`, not a string. Tests
  check every such value the server sends is a real key of that model.
- **Validation and input contracts** — every field the server validates, every error key it returns and every
  input key it reads must be a field of the action's input type. That verifies the payloads declared for Fortify
  against what Fortify really validates and reads (each declared field must be used), and makes non-field errors
  flash toasts.
- **TypeScript 7** strict + `noUncheckedIndexedAccess`; Eloquent strict mode at runtime.

`composer ci:check` runs everything (≈20 s): generate → pint → phpstan → lint/format → pest (+contracts) →
contract coverage → tsc.

Read **[docs/type-safety.md](docs/type-safety.md)** before writing code: it is the whole standard in one page.

## Differences from the official starter kit

- Every page's props, the shared props (`auth.user` is correctly `UserData | null`), flash data and the
  passkey/2FA settings are generated instead of hand-written (the hand-written ones had drifted from reality).
- Pest 5 instead of PHPUnit; PHPStan `max` (was level 7) with strict-rules and type coverage.
- TypeScript 7 (≈6× faster `tsc`), stricter `tsconfig.json`.
- pnpm; CI runs the full `ci:check`.
- `Route::redirect()` replaced (it registers the Laravel 13 `QUERY` verb, which Wayfinder 0.1.21 cannot type yet:
  laravel/wayfinder#326).
